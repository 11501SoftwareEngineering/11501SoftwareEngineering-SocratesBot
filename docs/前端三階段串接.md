# 前端三階段串接

本版實作教師與學生的新介面及 MSW 示範流程。API 型別與呼叫集中於 `frontend/src/api/inquiry.ts`；正式後端尚須依這份合約補齊新端點與驗證，前端示範不會呼叫真正的 AI。

## 最新產品決定

- 以帳號登入及管理，不使用電子郵件；只保留初次登入強制設定密碼，不提供後續自行改密碼或忘記密碼流程。
- 課程及活動皆直接刪除，沒有封存。刪除課程會連帶刪除成員關係及全部活動資料；刪除活動會連帶刪除該活動的對話、個人報告與摘要。畫面提供不可復原的影響說明及確認。
- 同一課程可同時發布任意數量的活動；「已發布活動」只呈現數字，不顯示上限或額外提示。
- 活動發布後八欄、內容語言與模型鎖定；舊設定頁僅供檢視，新舊修改端點均拒絕覆寫或隱式另存。草稿仍可編輯，摘要草稿及發布遵守獨立版本規則。
- Header 直接顯示「我的課程」，不折成選單，不重複顯示課程名稱；課程名稱保留在頁面主標題。教師與學生皆移除 SocratesBot 側欄。

## 頁面與流程

1. `/teacher/courses/:courseId/topics/new`：年齡層為 13–15、16–18、大學及以上（`university_plus`），回合上限為 5/10/15。課程描述 20–6000 個 Unicode 字元，首尾空白不計。AI 直接產生八欄並進入「檢視並確認」；最多三題補充方向併入回饋區，不顯示獨立釐清頁，也不阻擋教師編輯與發布。
2. AI 整理八欄：年齡層、回合上限、主題、核心探究問題、探究重點、必要背景資訊、排除事項、開場訊息。八欄均可修改；排除事項未指定時填「未指定」。補充檔案暫不實作。
3. 設定頁保留「給 AI 的回饋／釐清回答」與「依回饋重新產生」；範本及重新開啟的設定也可使用。開場訊息可獨立重新產生，不變更其他欄位；產生結果須另行儲存或發布。既有設定工作的釐清題數不因重產而歸零。
4. 研究主題庫提供 18 個可編輯範本與來源連結，模型清單由 API 提供。範本不取代教師已選的年齡層與回合數。
5. `/student/courses/:courseId/topics/:topicId`：每名學生有獨立對話脈絡。一次完整回合為 AI 訊息加學生回答；開場是第一回合的 AI 訊息，不先扣一回合。回答儲存後完成一回合。達到上限直接完成；目標達成時，必須等學生明確同意才可提前完成。退出為 `ABANDONED`，不納入完成統計。
6. 學生對話綁定開始時的設定與模型版本。串流請求帶 `request_id`，相同請求重試不得重複儲存回答或扣回合；重新進入以伺服器保存的紀錄及回合數為準。
7. 完成後產生結構化個人報告：立場、理由及訊息證據、其他觀點、轉折、未解問題、限制及完成原因。未表達明確觀點時保留未定狀態。
8. `/teacher/courses/:courseId/topics/:topicId` 提供「摘要審閱」「學生報告」兩個分頁。老師的摘要編輯區塊及學生版預覽已移除；舊 `?tab=preview` 連結轉回摘要審閱。由實際報告動態分群，沒有預先設定的結論類別。每份報告僅計入一組或未定集合；人數與比例依報告 ID 計算。保留可用報告、完成數及全班人數的不同分母。
9. 學生報告以動態觀點群組作為 tag；未明確表態者標示「尚未形成明確觀點」，新增且尚未納入摘要者標示「待重新分群」。點擊 Perspective 卡片切至 `?tab=reports&tag=<group_id>`；清單顯示 tag，可搜尋 tag 名稱、清除篩選或點擊 tag 篩選。
10. 摘要須經教師審閱後才能發布。修訂產生新草稿；學生只讀不可變的已發布版本，不能讀取其他人的個人報告、成員識別碼或報告 ID。教師預覽不等同已向學生發布。

## 新 API 合約

所有路徑位於 `/api/v1`，需要 Bearer token。教師端驗證課程所有權；學生端驗證身分、課程成員關係及 Session 所有權。

| 方法與路徑 | 用途 |
| --- | --- |
| `GET /teacher/inquiry-models` | 可用模型選項 |
| `POST /teacher/courses/:courseId/setup-jobs` | 建立最多三題釐清的設定工作 |
| `POST /teacher/courses/:courseId/setup-jobs/:jobId/answers` | 提交或略過釐清回答 |
| `POST /teacher/courses/:courseId/setup-jobs/:jobId/refine` | 依回饋重產，保留工作題數 |
| `POST /teacher/courses/:courseId/setup-revisions` | 修訂範本或已儲存設定 |
| `POST /teacher/courses/:courseId/opening-message` | 僅重產開場訊息 |
| `GET /teacher/topics/:topicId/setup` | 讀取八欄、語言、模型及版本 |
| `POST /teacher/courses/:courseId/inquiries` | 儲存草稿或發布，附 `expected_version` |
| `DELETE /teacher/topics/:topicId` | 連帶刪除活動全部資料 |
| `DELETE /teacher/courses/:courseId` | 連帶刪除整個課程全部資料 |
| `GET /teacher/topics/:topicId/reports` | 結構化報告集合及處理數量 |
| `GET /teacher/topics/:topicId/summary` | 取得草稿及獨立發布快照 |
| `POST /teacher/topics/:topicId/summary` | 根據可用報告產生新摘要草稿 |
| `PATCH /teacher/topics/:topicId/summary` | 修訂概述、觀點總結，附版本 |
| `POST /teacher/topics/:topicId/summary/review` | 標記教師完成審閱 |
| `POST /teacher/topics/:topicId/summary/publish` | 發布已審閱版本 |
| `POST /teacher/topics/:topicId/summary/withdraw` | 撤回學生存取，保留教師草稿 |
| `POST /student/sessions/:sessionId/end` | `complete`、`continue` 或 `abandon` |
| `GET /student/sessions/:sessionId/report` | 僅限學生自己的報告及處理狀態 |
| `GET /student/topics/:topicId/summary` | 僅回傳已發布摘要，去除報告關聯 ID |

設定及摘要採版本衝突檢查（409）；欄位不合法為 422。報告狀態支援 `pending / processing / ready / failed`，前端會針對未完成的報告輪詢。

## 完成示範與正式串接差異

「哲學概論 → 善意的謊言是對的嗎？」直接提供完成示範：12 份報告、3 組觀點、2 位尚未形成明確觀點者及已發布摘要。這是虛構的已完成資料，不需要額外示範按鈕或另一個活動。既有瀏覽器假資料依示範版本升級這個內建範例；已刪除的範例不會重新建立。

示範的設定整理、開場變體、目標判斷、報告及文字相似度分群皆為本機模擬。正式後端仍須實作 AI 工作、語意改寫與分群、證據核對、模型版本鎖定、取消與重試、審閱發布驗證、報告處理排程、資料庫交易式連帶刪除及完整權限檢查。前端已移除後續改密碼入口，正式密碼端點也須限制於初次設定。

個人報告參照提供的報告結構，補入觀點總結、目前立場、最強理由、已檢驗的挑戰、修正或辯護、與探究重點的連結、尚待追問、觀點變化時間軸及未完成或證據不足。`viewpoint_summary` 必須忠於保存的學生回答；`evidence_status` 區別 `sufficient / partial / insufficient`，完成回合不等於已形成明確立場。未回答的追問不可推定已通過檢驗，外部事實不可寫成已查證。

全班摘要保留 `viewpoint_summary` 與動態群組。老師摘要審閱不顯示全班時間軸、內層摘要編輯區或學生版預覽；個人報告時間軸仍保留，只有學生明確指出時才標示提問與改變的因果。教師可由相關 tag 查看個人報告。有授權的助教可修訂摘要草稿，修訂後須交老師重新審閱再發布；學生端只讀公開快照，不取得個人訊息、原話、匿名代碼或報告關聯 ID。舊觀點分歧點、全班討論問題及獨立支持理由與對話證據區塊皆已移除。

介面主要標籤有繁體中文、英文及西班牙文切換；固定教學說明尚有中文內容，正式國際化仍須補齊。內容語言與介面語言分開；示範範本以繁體中文提供。

## 驗證

在 `frontend` 內執行 `pnpm lint`、`pnpm build`、`pnpm build:demo` 及 `pnpm exec vitest run`。Node 26 若遇原生 localStorage 與 jsdom 衝突，可用 `NODE_OPTIONS=--no-experimental-webstorage pnpm exec vitest run`。


## 助教功能

助教沿用一般帳號，依 `CourseMembership.role = TA` 指派到課程，不新增全域管理員身分。登入及 `/users/me` 回傳 `has_ta_assignments`；有助教課程時，預設進入教學課程列表，也可切換「學生課程」。課程回應包含 `access.role / access.permissions`。一般學生即使改寫前端狀態，仍會被 API 的課程及操作檢查阻擋。

老師在「課程 → 助教與權限」輸入既有帳號，為每名助教勾選：

| 權限 | 範圍 |
| --- | --- |
| `view_reports` | 個人報告、tag 及時間軸 |
| `edit_activities` | 八欄、AI 整理及活動草稿 |
| `edit_summary` | 產生及編輯摘要草稿 |
| `view_members` | 學生名單及課程代碼 |

助教可查看被指派課程的基本活動與摘要。發布、標記審閱完成、撤回發布、刪除、管理助教及老師 API key 皆限課程老師。角色、個別權限及課程範圍於每次 API 請求檢查，不以隱藏按鈕取代授權。

新增 `GET/POST /teacher/courses/:courseId/tas`、`PATCH/DELETE /teacher/courses/:courseId/tas/:memberId`。助教不列入學生名單及人數；原學生改任助教時保留對話，撤銷助教後恢復原學生身分。範例帳號為 `ta / password123`，初始指派哲學概論，提供四項協助權限；老師可自行取消。首頁及 Debug 面板提供助教體驗入口。

正式後端既有課程成員 TA 欄位可沿用，仍需實作授權欄位、成員管理端點及角色回應；本次未修改資料庫結構。

## 教師 AI 設定、模型與金額

教師課程首頁將 token 用量、模型選擇及 OpenRouter 本月已用金額整合為「AI 模型與用量」單一卡片，共用重新整理按鈕並保留 API key 設定入口；`/teacher/ai-settings` 使用同一卡片，另顯示完整階段用量及 API key 欄位。

| 方法及端點 | 資料 |
| --- | --- |
| `GET /teacher/ai-usage` | 本帳號、當月總輸入及輸出 token、請求次數、階段統計、`usage_monthly_usd`、金鑰上限及剩餘金鑰額度 |
| `GET /teacher/ai-settings` | 設定狀態、遮罩、預設模型；不回傳完整金鑰 |
| `PUT /teacher/ai-settings` | 寫入金鑰，回應僅含狀態及遮罩 |
| `DELETE /teacher/ai-settings` | 移除金鑰設定，保留課程及模型偏好 |
| `PATCH /teacher/ai-settings/model` | 儲存新活動預設模型 |

依 5173 參考頁保留 GPT-6 Luna、GPT-5.4 Mini、GPT-4.1 Mini、GPT-6 Sol 四項示範選項與價格。`ModelOption.pricing` 明確使用美元／百萬輸入及輸出 token，並標示來源與更新時間。新活動預設取老師的模型設定；已發布活動及學生 Session 維持自己的設定快照。助教的授權 AI 操作計入課程老師。

金額顯示 OpenRouter 的本月已用，與本系統 token 統計分開。未提供的金額顯示「尚無資料」，不當作零；未設定金鑰支出上限時不換算剩餘 token。正式後端可由 [OpenRouter 當前金鑰 API](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key) 正規化 `usage_monthly / limit / limit_remaining`；一般金鑰無法取得需要管理金鑰的 [帳戶總額度 API](https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits)。模型價格取自 [模型目錄](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) 的每 token 美元價格，正規化成每百萬 token 後才交給前端。

示範版用量與金額是模擬數據，價格沿用參考頁，沒有呼叫或計費 OpenRouter。示範版金鑰只留下設定狀態及尾碼遮罩，完整文字不進入 localStorage、Pinia、網址、回應或日誌，送出即清空輸入欄。正式版仍需後端實作安全保存金鑰、使用 provider 回傳的實際 token／cost、支出查詢及錯誤處理；助教無權讀取或改寫老師的金鑰。
