# 開發用測試資料

給**前端**在本機對真實後端按按鈕用的帳號與課程資料。  
下列指令在 **repo 根目錄**執行（有註明 `frontend/` 的除外）。

## 要執行的指令

### 第一次／後端還沒起來

開兩個終端即可。

**終端 A — 資料庫 + 假資料 + 後端**

```bash
# 1. 啟動本機 Postgres（若尚未在跑）
make -C backend db-dev

# 2. 灌入開發假資料（可重複執行，不會重複建帳號）
make -C backend seed

# 3. 啟動後端 API
make -C backend dev
```

**終端 B — 前端**

```bash
cd frontend
pnpm install   # 第一次或依賴有變時
pnpm dev
```

瀏覽器打開前端網址（通常是 Vite 印出的位址），API 請指向本機後端。

### 假資料弄亂了（一鍵恢復）

後端停掉後，在 repo 根目錄：

```bash
make -C backend db-reset
```

終端會問你是否清空再重建；確認後會自動再跑 seed。  
若腳本／自動化不能互動，改用：

```bash
make -C backend db-reset CONFIRM=1
```

恢復後再 `make -C backend dev`，前端繼續 `pnpm dev`。

### 只想再灌一次假資料（不清空整庫）

```bash
make -C backend seed
```

## 登入帳號

三個帳號**密碼相同**：`password1`

| 帳號 | 用途 |
|------|------|
| `dev-student` | 學生流程（課程、進入對話／session 等） |
| `dev-teacher` | 老師流程 |
| `dev-admin` | 管理員流程（老師名單等）；後端需已把此帳號設成 super-admin |

`make seed` 跑完後端終端會再印一組摘要，方便複製。  
登入後若 role 與前端路由對不上，先跟後端確認 API 回傳的 role 字串。

## 示範課程（學生已加入）

| 項目 | 值 |
|------|-----|
| 邀請碼 | `DEVJOIN01` |
| Topic ID（進 session／相關 API 用） | `00000000-0000-4000-8000-000000000201` |

學生帳號 `dev-student` 已在這門課裡，一般不必再手動加入。  
若畫面要測「輸入邀請碼加入」，可用上面的邀請碼。

## 建議怎麼測

1. 依上方指令把 DB、seed、後端、前端都開好。  
2. 用上表帳號登入，依角色走對應頁面。  
3. 需要打「依 topic 進 session」之類 API 時，用上表 **Topic ID**。

## 注意

- 這些帳號**只給本機開發**，不要當正式環境帳密。  
- 帳號／邀請碼／Topic ID 若與 `make seed` 印出的摘要不一致，以當次印出的為準，並請更新這份文件。
