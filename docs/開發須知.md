# 專案開發規則
## Github 分支管理
1. 禁止直接 push commit 到 main branch，所有改動必須在其他 branch 進行。要合併時開 pull request，至少一人 review 後才能合併，通常是由組長。
2. 一個 pull request 以一個功能為主，不要將多個不相干的改動合在一起提交。
3. 採用 Squash and Merge，將瑣碎的 Commit 壓平成一個乾淨的紀錄。
4. 發 pull request 時請先經過測試，最少要手動測試執行沒有問題，不要一堆 bug 連正常執行都不行。
5. 命名規則
    - commit message: `<type>(<scope>): <subject>`
    - branch name: `<type>/<subject>`
    - PR title: `<type>(<scope>): <subject>`

    type：
    - feat：新增或修改功能
    - fix：修復錯誤
    - docs：文件修改，沒有動程式碼
    - style：調整格式，不影響程式碼邏輯（如空格、分號、排版等）
    - refactor：重構程式碼（既不是新功能，也不是修 bug）
    - perf：效能改善
    - test：增加或修改測試程式碼
    - chore：建構程序、輔助工具或日常維護變動
    - build：影響系統建置的變動，例如 DevOps 與增加套件
    - ci：持續整合相關設定與腳本的變動。

    scope：
    - frontend
    - backend
    如果是 docs, build 或全域設定的情況下可省略

## 資料庫
1. 資料庫欄位若需要改動請先討論，並使用 migration (目前預計用 python alembic) 變更。

## LLM
1. API key 應在 .env 等環境變數中設定，不要直接寫死在程式中，push 時也請檢查，避免外洩。

# 後端
## 環境建置

1. 請確認本機已安裝以下工具：
    - Docker & Docker Compose
    - uv

2. 複製 .env 檔：
    ```bash
    cp .env.example .env
    ```

3. 建立 Python 虛擬環境與套件安裝
    ```bash
    cd backend
    uv sync
    ```
    uv 會讀取 pyproject.toml 與 uv.lock，建立虛擬環境 backend/.venv 並自動安裝套件。

### 啟動開發伺服器
1. 啟動 docker 容器，裡面有 PostgreSQL 和 Redis. 
    在專案根目錄執行 docker compose up：
    ```bash
    docker compose up -d
    ```

    檢查容器狀態：
    ```bash
    docker compose ps
    ```

    關閉容器
    ```bash
    docker compose down
    ```
2. 啟動 fastapi
到後端資料夾下執行
```bash
uv run fastapi dev app/main.py
```
到 http://localhost:8000 應該就可以看到了

### Python 環境
請不要直接使用 python 或 python3 指令，用 `uv run <.py file>`。這樣才會使用 uv 的建立環境
要新增修改任何套件，也請使用 uv 操作，不要直接使用 pip
