# SocratesBot 原型前後端開發規格書

版本：v0.2 prototype

文件日期：2026 年 10 月 30 日

交付狀態：DO NOT MERGE 草稿 PR，供產品確認及前後端分工

適用對象：前端、後端、AI 流程與測試開發人員

## 1 文件目的與版本基線

本文件將 v0.2 原型轉成可實作及驗收的開發規格。產品採三階段流程：老師設定活動，學生各自進行蘇格拉底對話，系統依結構化個人報告整理全班觀點，由老師審閱後發布。功能以本文件及此次確認的原型為基線；舊規格與本版衝突時，以本版決定為準。

第 15 節按實際路由、頁面及操作盤點目前所有功能，包含可操作原型、瀏覽器原生能力、保留 API、示範工具及尚未連結的占位項目。盤點中的「可操作」指原型狀態，不代表正式後端已完成；開發分工、資料及驗收仍須對照第 9 至第 14 節。

目前可直接執行的是 Vue 前端與瀏覽器 MSW 假後端。帳號、對話、AI 整理、報告、分群、token 與金額皆有示範流程；展示成功不代表正式 AI 或資料庫 API 已完成。原型資料保存在本機瀏覽器，不會呼叫 OpenRouter，也不應輸入真實學生資料或真正的 API key。

已檢查的正式後端包含驗證、使用者、管理員教師管理，以及學生進入 Session 與匿名設定等路由。`CourseMembership` 已有 STUDENT／TA，`Session` 已有每位使用者每個活動唯一一筆的限制；八欄設定、助教細部權限、訊息串流、個人報告、動態分群、摘要發布及 AI 計費等仍需正式串接。後端項目的完成狀態應依實際程式與測試確認。

## 2 角色與權限

正式後端的全域角色沿用 USER、TEACHER。助教是一般帳號在特定課程的 TA 成員資格，不新增全域 TA 或管理員角色。管理員沿用既有設定提升機制；不能只根據前端的 SUPER_ADMIN 字串放行。

| 操作 | 課程老師 | 指派助教 | 學生 |
| --- | --- | --- | --- |
| 查看教學課程與活動 | 自己的課程 | 被指派課程 | 僅學生課程入口及已發布活動 |
| 建立與編輯課程 | 可以 | 不可 | 不可 |
| 建立及編輯活動草稿 | 可以 | 需 edit_activities | 不可 |
| 修改已發布活動 | 不可 | 不可 | 不可 |
| 發布或刪除活動與課程 | 可以 | 不可 | 不可 |
| 查看個人報告及觀點 tag | 可以 | 需 view_reports | 只可查看自己的報告 |
| 產生摘要草稿 | 可以 | 需 edit_summary | 不可 |
| 編輯摘要文字 | 老師頁面不提供此區塊 | 需 edit_summary，可修訂草稿 | 不可 |
| 審閱完成與發布或撤回摘要 | 可以 | 不可 | 不可 |
| 查看學生名單及課程代碼 | 可以 | 需 view_members | 不提供教師名單管理功能 |
| 指派或移除助教及勾選權限 | 可以 | 不可 | 不可 |
| 設定老師 API key 與預設模型 | 本人 | 不可 | 不可 |

老師新增助教時輸入既有帳號，再勾選權限。不得由助教修改自己的權限，跨課程的相同權限也不得互通。每次 API 請求均須重新檢查課程所有權、成員資格及細部權限，不能以隱藏按鈕作為安全控制。

助教不計入學生名單、全班人數、完成數或報告分母。原學生改任助教時保留歷史對話，從現行學生統計排除；撤銷時原型會恢復原學生身分。正式版須保存角色變更紀錄並確認發布摘要遇到名單異動的處理方式。

管理員的教師帳號建立、查詢、刪除與既有存取保護繼續保留；管理員身分不自動等於可閱讀所有課程的學生對話。

## 4 階段一 活動設定

老師先選學習者年齡層、回合上限、內容語言，並輸入課程描述。年齡層只允許 `13-15`、`16-18`、`university_plus`，不沿用舊版成人年齡範圍；回合只允許 5、10、15。原型描述限制為去除首尾空白後 20 至 6000 字元，正式前後端須統一 Unicode 計數方式。

補充 PDF、PPTX、TXT 上傳不納入 v0.2。研究主題庫提供原型的 18 個參考主題，套用後仍由老師確認八欄，不強迫使用特定主題或標準立場。

| 欄位 | 欄位代碼 | 產生及驗證規則 |
| --- | --- | --- |
| 學習者年齡層 | age_band | 沿用老師選擇，只接受三種列舉。 |
| 對話回合上限 | max_turns | 沿用老師選擇，只接受整數 5、10、15。 |
| 主題 | topic | 擷取並整理課程名稱，不得空白。 |
| 核心探究問題 | core_question | 由 AI 提議，可在草稿修改，不得空白。 |
| 探究重點 | inquiry_focus | 擷取描述或提出建議，不得預先指定學生必須接受的結論。 |
| 必要背景資訊 | background_info | 整理開始對話前需要的情境與定義，不把未查證資訊寫成事實。 |
| 排除事項 | exclusions | 擷取老師限制；無限制時明確填「未指定」。 |
| 開場訊息 | opening_message | AI 產生，可在草稿單獨重產；同活動及相同內容語言共用。 |

釐清題總數在同一設定工作中最多三題，回答或重新產生不重設累計。釐清題放在「給 AI 的回饋／釐清回答」附近供參考，不再以獨立頁面阻擋八欄確認。AI 提供建議後，老師可直接修改全部八欄。

「依回饋重新產生」應保留手動修改作為修訂輸入；單獨刷新開場只更新 opening_message。兩者都不得自行發布或覆寫已發布活動。發布前須顯示確認，包含內容語言、模型及發布後無法修改。

### 活動狀態與鎖定

活動只有 draft、published 兩種業務狀態，另可被刪除。草稿修訂使用 expected_version 檢查；第一次發布將草稿原子性轉成 published，固定其八欄、語言與模型。

發布後不得退回草稿、修改、換模型、換開場或以原活動 ID 另存一份活動來繞過鎖定。新建不同活動應使用明確的新建流程。一般新建活動及同課程同時發布的活動數量不受此規則限制。

前端移除編輯入口，舊編輯路徑顯示唯讀資料。後端須在交易內重新檢查狀態與版本，避免同時發布及儲存的競爭；新舊修改 API 都須回傳 409，原型訊息為「活動已發布，無法再修改。」。活動刪除及全班摘要發布使用各自規則。

## 5 階段二 學生獨立對話

每位學生在每個活動有自己的 Session，重新進入回復既有進度。Session 固定活動設定、內容語言、模型及設定版本，不共用其他學生的上下文。相同活動的開場與模型一致，內容則依個別回答發展。

一回合定義為 AI 發出一則訊息，接著學生回覆一則。第一則開場是第一回合的 AI 訊息；只載入開場還不算完成一回合。學生第 N 次成功回覆後 completed_turns 為 N，剩餘回合為上限減 N。達上限後不再發出新的提問或接受超額回覆。

正常完成條件只有兩種：達成探究目標且學生明確同意結束，或已達回合上限。達成目標時可選擇繼續；未達上限且未同意時不能自動結束。目標指引導學生表達立場、理由及檢視不同觀點，不代表得出正確答案。

原型另有「退出」並標記 ABANDONED；退出不是完成，不產生完成報告、不列入完成數。正式後端目前的 Session 狀態限制需擴充；是否允許退出後重開，列為待決事項。單純離開頁面只保留進度。

### 串流與重試契約

前端傳送 content 與 request_id，同一筆重試沿用相同 request_id。後端以 Session 及 request_id 做唯一性及併發控制，重送不得重複儲存回答、扣回合或再次扣計費。不同 request_id 若同時送至同一 Session，也須序列化或回傳明確衝突。

串流使用 text/event-stream。一般 data 事件是可直接接續的文字；最後一個 done 事件回傳已保存的 message_id、remaining_rounds、is_completed 及 awaiting_end_consent。串流結束後，前端以後端訊息紀錄重新校準。

若送出後斷線，前端先查歷史及 request 狀態再決定重試，不因尚未收到 done 就建立第二筆新請求。發送期間鎖定再次送出，顯示重試或重新載入選項；關閉頁面及取消等待不應把已保存的回答當成不存在。

## 6 結構化個人報告

正常完成對話後，由後端建立報告工作，狀態為 pending、processing、ready、failed。報告失敗不改回對話進行中，也不要求學生重談。再次處理須沿用原對話，並以版本保存結果。

| 資料 | 必要內容 |
| --- | --- |
| 識別及完成資訊 | report_id、version、session_id、topic_id、anonymous_id、completed_at、completed_turns、completion_reason。 |
| 觀點摘要 | viewpoint_summary、final_viewpoint、viewpoint_status；區分已表態與未形成明確觀點。 |
| 最強理由及挑戰 | 理由、對應訊息、最強理由、已檢驗挑戰、學生是否實際回應。 |
| 修正與探究連結 | revision_or_defense、focus_connection、other_perspectives、open_questions。 |
| 證據品質 | evidence_status 為 sufficient、partial、insufficient；保留 limitations。 |
| 觀點變化時間軸 | 回合、提問、回覆證據、提問前後觀點、變化類型及因果依據。 |

證據引用使用 message_id、turn、quote，必須能回查真正保存的學生訊息；不能把 AI 的話當成學生理由。沒有回答的挑戰須標記未回應，外部說法不能寫成已查證。

時間軸的 attribution 區分 explicit、sequence_only、none。只有學生明確指出某個問題使其修改時，才可以描述因果；其餘僅呈現對話先後。正常完成也可能只有部分證據，不能自動標為充分或已形成明確立場。

個人報告畫面保留觀點總結、目前立場、最強理由、已檢驗的挑戰、修正或辯護、與探究重點的連結、尚待追問、限制與時間軸。舊的獨立理由證據區已移除，引用資料仍供內部核對與時間軸查詢。

## 7 階段三 動態觀點分群與發布

後端以 ready 狀態的結構化報告及已發布活動設定作為摘要輸入。原始對話保留供證據查核，不直接把全班完整逐字稿當成一般摘要的唯一輸入。相近觀點依實際主張、條件與理由動態分組，不依預先建立的結論清單分類。

每份可用報告只能屬於一組或未定集合。group.count 應由不重複 report_ids 計算；percentage 的分母為可用報告數。全班人數、完成對話數、可用報告數、處理中與失敗數分開呈現。無立場、無回答及未完成不能當成支持或反對。

內建「善意的謊言」示範為 12 份報告，三組人數分別為 4、3、3，另有 2 位未定；比例為 33.3%、25%、25%，未定部分為 16.7%。分組比例合計不必是 100%，但所有集合須涵蓋分母且不得重複。

老師頁面只顯示觀點分布、觀點總結、各組條件、人數與比例，以及審閱發布控制；不顯示全班時間軸、討論問題、手動摘要編輯區或學生版預覽。個人報告時間軸仍可由有權限者查看。

老師或有 edit_summary 的助教可產生新摘要草稿；有授權的助教保留修訂草稿文字功能。老師確認統計範圍與表述後標記審閱完成，再發布給學生。文字修訂或重新分群會撤銷該草稿的審閱狀態。

摘要狀態為 draft、reviewed、published、withdrawn。published 是不可變的發布快照；新增報告、助教修訂或重新產生只更新新草稿，不改變學生正在看的版本。老師撤回後，學生 API 不再回傳該摘要。活動已發布的設定鎖定，不限制另外建立摘要草稿。

Perspective 的 group_id 是報告 tag 的來源。未定者標記「尚未形成明確觀點」，新報告尚未納入目前摘要時標記「待重新分群」。更換摘要版本後，前端須更新 tag 對應，避免沿用舊分類名稱。

學生只能取得已發布的公開摘要，不得取得同學姓名、匿名代碼、原始引言、session_id、message_id、report_id 或群組的 report_ids。原型回應會清空部分關聯欄位；正式版應設計獨立公開 DTO，由後端產生安全投影。

## 8 模型 金鑰與用量

「AI 模型與用量」卡片整合總 token、輸入 token、輸出 token、請求次數、新活動預設模型、USD 本月已用及模型單價。一個更新按鈕同步更新資料。模型偏好只影響之後的新活動；發布過的活動及既有 Session 維持鎖定模型。

原型提供 GPT-6 Luna、GPT-5.4 Mini、GPT-4.1 Mini、GPT-6 Sol 四個參考選項。正式模型 ID、可用性、價格及支援能力應由後端供應商目錄提供，不能把示範名稱或金額當成正式計費承諾。

老師在自己的設定頁填入 API key。前端以遮蔽欄位輸入，送出後清空，不將完整 key 寫入網址、Pinia、localStorage、分析事件、錯誤日誌或回應。正式後端安全保存加密值或密鑰參照，回應只提供 configured、masked_key、updated_at 及模型偏好。助教與學生均不得取得或修改 key。

授權助教的 AI 操作及學生對話應歸屬課程老師的計費主體。後端按真正的供應商回應記錄模型、token、美元成本、時間、階段、請求及使用金鑰版本；重試、快取與串流重放不得重複記帳。更換 key 不抹除既有用量歷史。

應區分「本系統的 token 用量」與「目前 OpenRouter key 的本月已用」。兩者可能因統計範圍、key 更換及其他系統使用而不同。未提供的金額顯示尚無資料，不能當成零；未設支出上限不能推算剩餘 token。若來源有金鑰上限及剩餘金額，可顯示 USD；不以一般 key 假定可取得帳戶總餘額。

### 共用錯誤與登入契約

沿用目前登入回應的 Authorization header 與使用者 profile。正式版需要補上 has_ta_assignments 及管理員能力資訊；管理員是設定提升，不可依 MSW 的 SUPERADMIN 角色假定正式路由可用。刷新 Cookie、CSRF、CORS 與登出應對齊既有後端安全流程。

狀態碼基線為 401 未登入或過期，403 身分／課程／權限不允許或初次密碼未完成，404 不存在或不對外揭露的資源，409 版本衝突、狀態衝突或已發布鎖定，422 欄位錯誤，429 頻率限制，502／503 供應商或服務失敗。正式錯誤格式建議增加穩定 code 及 request_id，保留 detail 作顯示對照；格式變更須同步前端。

## 12 安全 國際化與非功能要求

所有資料存取須驗證登入者、課程關係及資源所有權。對話、報告及摘要不能因可猜測的 ID 而外洩；一般學生偽造 role 或助教 permission 不得通過。老師只能使用本人 key，課程助教不能修改計費主體。

輸入內容及模型輸出都視為不可信文字，限制長度、驗證結構並安全呈現；不可將 HTML、連結或上傳內容中的文字當作系統指令。提示注入不應改變授權、洩露 key 或讀取其他學生上下文。報告引用及分群集合須由程式驗證。

沿用既有密碼雜湊、登入／刷新保護與傳輸加密要求。日誌不記錄完整 key、密碼或逐字稿；記錄必要的 request_id、狀態與去識別錯誤以供排查。token 與費用以可稽核紀錄計算，避免浮點累積誤差。

介面語言保留繁體中文、英文、西班牙文；內容語言與介面語言分開。完整翻譯固定提示、錯誤、驗證、權限及鎖定訊息；研究主題以來源語言標記，不假設切換 UI 就已翻譯課程。後端存 UTC，介面以明確時區顯示；月用量區間及供應商時間邊界須統一。

桌機與窄螢幕皆可完成主要流程，Header 導覽直接可見，鍵盤可操作表單、分頁、確認及對話。淺色背景使用有足夠對比的深色文字，載入、空資料、失敗與重試均有可讀狀態；不能只以顏色表示發布或權限。

AI 逾時、供應商限流、無 key、無額度及報告失敗均需可理解的狀態。工作重啟、重試及取消須確保不重複完成或計費。併發人數、AI 延遲、可用性與成本告警門檻由團隊確認，不把原型等待時間當成正式服務承諾。

### 學生課程 對話與結果

| 編號 | 功能 | 現況與實作要求 |
| --- | --- | --- |
| STU01 | 我的課程及搜尋 | 按課名、代碼、老師搜尋，顯示老師、活動數、代碼及進入課程。 |
| STU02 | 加入課程 | 代碼去首尾空白並轉大寫，成功回饋並刷新列表，顯示不存在／重複等錯誤。 |
| STU03 | 退出課程 | 確認後撤銷本人課程存取，成功提示；不刪除老師的整門課。 |
| STU04 | 活動列表與進度 | 顯示名稱、描述、回合及尚未開始／進行中／完成；可開始、繼續或查看自己的報告。 |
| STU05 | 建立與重入 Session | 本人同活動重用既有 Session，固定開場、設定及模型，恢復自己的上下文。 |
| STU06 | 文字輸入與送出 | 多行輸入、6000 字上限、Ctrl／Command 加 Enter，避開輸入法組字；空白、送出中及辨識中限制送出。 |
| STU07 | 略過這題 | 以「略過這一題」送出明確學生回覆，照規則計一回合；不能據此推定學生立場。 |
| STU08 | 串流與等待呈現 | 逐段顯示 AI 文字、處理指示與剩餘／已完成回合，發送期間避免重複操作。 |
| STU09 | 重入及斷線復原 | 以後端紀錄校正，重試沿用 request_id；不確定是否保存時先恢復紀錄，再允許繼續。 |
| STU10 | 達目標後結束或繼續 | 目標達成才提供同意完成或繼續思考；未同意且未達上限不自動完成。 |
| STU11 | 上限自動完成 | 第 5／10／15 個成功回覆後自動結束，不再提問，進入報告結果。 |
| STU12 | 退出探究 | 經確認標 ABANDONED，保留已存紀錄但不算完成、不納入全班摘要；一般離頁可恢復進度。 |
| STU13 | 探究背景 | 對話側欄顯示背景、載入狀態及重新取得背景入口。 |
| STU14 | 語音輸入 | 申請麥克風、開始／停止錄音、上傳辨識並把文字附加輸入框；可再編輯，不自動送出。Mock 可用假錄音及假轉錄。 |
| STU15 | AI 訊息朗讀 | 瀏覽器 speechSynthesis 朗讀、再次按下停止；切換訊息取消前一段、離頁停止，使用內容語言；不支援時顯示提示。 |
| STU16 | 完成後結果入口 | 完成後可從對話頁或活動卡進入自己的結果頁，不進入別人的 Session。 |
| STU17 | 報告等待與失敗 | pending／processing 每 3 秒查詢，ready 顯示，failed 提示失敗及重新載入；不要求重談。 |
| STU18 | 本人個人報告 | 結果頁的個人報告分頁呈現結構化內容及時間軸，只能讀本人。 |
| STU19 | 對話紀錄及證據跳轉 | 本人結果頁可查看逐字訊息；點最強理由或時間軸證據切到紀錄並捲至對應訊息。 |
| STU20 | 已發布全班摘要 | 結果頁的全班摘要分頁只讀老師發布版本，未發布顯示等待，原型每 15 秒更新；無他人報告入口。 |
